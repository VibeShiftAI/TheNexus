## Trace: where the separate sign-in came from

Robert's Mac cockpit is *The Nexus.app* (`desktop/src-tauri/src/main.rs`, macOS personality, launched at login by the "The Nexus" LaunchAgent). It is a single WKWebView on **`http://localhost:3000`** — no Cloudflare Access is involved there. Its window handler (`main.rs:151-171`) denies every new-window request and hands http(s) URLs to the system browser. The phone shell and the Windows travel shell load `https://nexus.vibeshiftai.com` behind Cloudflare Access instead.

Praxis's message in the live conversation (`3abe0db4-…`, message `ad355745-…`, 2026-09-10 13:06 local) links the report as the absolute URL the Nexus API mints (`server/services/document-review-format.js:9-18`, default `NEXUS_DASHBOARD_URL` = the tunnel host) and even says *"Sign in through the usual Nexus login if prompted."* At the dispatch baseline the chat renderer (`dashboard/src/components/chat/markdown-message.tsx`) treated only `/task/…` and `/inbox…` hrefs as in-app; every other link rendered `<a target="_blank" rel="noopener noreferrer">`. So from the Mac app the click went to the system browser at `nexus.vibeshiftai.com`, which has no Access cookie → Cloudflare login. From a plain `localhost:3000` tab it opened a new tab on the tunnel host → the same login. From the travel shell, `open_in_browser` → the same login. On the phone shell the same absolute link is at least same-origin, but nothing in the Dashboard offered a way to reach documents without that link: the only in-app route was the *Documents for review* panel on the task page, which Robert had no reason to know about.

Anonymous access to the tunnel still redirects to Cloudflare Access (302 for the page, the API and `/documents`); that is the unauthenticated boundary, not the logged-in problem, and it is unchanged.

## Design and change (smallest coherent fix, dashboard only)

1. **Dashboard links stay in the Dashboard.** `dashboard/src/lib/task-links.ts` gains `internalHref(href)`: a same-origin path, or an absolute URL whose host is a dashboard host (`nexus.vibeshiftai.com`, `localhost:3000`, `127.0.0.1:3000`, or the page's own host) and whose first path segment is one of the App Router pages, collapses to `path + query + hash`; anything else (other hosts, look-alike hosts, the Access login host, `/api/*`, `/graph`, `/runs`, `/hub`, `/login`, `javascript:`, `//host`, userinfo) returns null. `isInternalHref` now delegates to it. `markdown-message.tsx` renders internal links through Next's `Link` on the current origin (task/inbox links keep their monospace style) and keeps `target="_blank"` for everything external.
2. **A visible entry point.** `nav-sidebar.tsx` gets **Documents — Reports for Review** (`/documents`), and the new `dashboard/src/app/documents/page.tsx` lists every registered document with kind, file, revision, task/project links, the reviewer's state (*Not reviewed yet* / *Draft · n comments* / *Review sent to Praxis* / delivery failed) and a filter for what still needs review. Its links are the relative reviewer route.
3. **Shared helpers.** `dashboard/src/lib/document-review.ts` adds `listDocuments(filters)`, `documentHref(id)` and `reviewStateLabel(entry)`; the task panel now uses them (same wire calls as before, `review-documents-panel.test.mjs` unchanged and green).
4. **Back/close from any origin.** The reviewer header (`document-review.tsx`) gains a **Documents** crumb next to **Task**, so a report opened from chat has an in-page way back to the list; the existing back link and browser history are untouched.

Nothing changed server-side: `review_url` stays the absolute canonical link (Praxis, push payloads and "Copy link" still need a shareable URL), authentication and path boundaries are untouched, the `/api/*` proxy seam is preserved, and no iframe or credential is involved.
