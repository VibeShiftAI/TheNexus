# Praxis proposals and linked highlights

Use superpowers:subagent-driven-development for bounded implementation and independent review. User explicitly requests replacing manual-first conversion with Praxis-proposed wording and selecting right-side suggestions to highlight the changed source on the left. This corrects the approved review flow; no additional approval step is needed.

## Design
Click Turn into suggested edit invokes the existing Praxis completion gateway, using canonical immutable document/comment context read on the server. Save one linked proposal as pending, attributed to Praxis, retaining the original executor comment. Existing Accept/Edit & accept/Reject/Undo/Apply remain the decision path; generation never accepts or applies. Stable request IDs and source-linked uniqueness prevent duplicate proposals after retries. Passage comments preserve their exact source range. For a document-wide comment Praxis selects one exact, unambiguous passage; invalid/ambiguous output fails visibly without changing the file. Failure offers retry and retains existing typed edits.

Click a suggestion card (or keyboard-select its passage control) scrolls the stage to its target, highlights the source words and selects the card. Controls/textarea/link interactions must not cause unexpected scrolling. Highlight only verified source/anchors; stale unmappable targets explicitly remain unavailable. Use existing Markdown block anchors and avoid reparsing Markdown on typing. Insertion uses an insertion-point indication; formatted Markdown may highlight its enclosing block with an exact original-text indication when raw offsets cannot be represented reliably.
