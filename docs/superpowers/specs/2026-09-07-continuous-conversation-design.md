# Persistent voice and optional conversation mode

Robert approved continuing the two next opportunities: voice across Nexus and optional follow-up listening. Keep the existing voice, transcription, chat context, tools and alert modes. Move the one VoiceCommandBar instance from the Bridge header into the persistent root layout, within the existing providers, using a compact fixed dock above the event ticker. Panels open upward and fit narrow screens. Hide/unmount voice on the login page; ordinary client navigation preserves the session and event subscription. Do not create multiple voice engines.

Conversation mode is an explicit, visible Start conversation / End conversation action, off on initial load and never persisted as armed. Starting it captures a turn. Only successful completion of that user's full spoken reply can arm the next capture after a short settling delay. Alerts and manual chat replay never start listening. Do not infer completion from generic idle state. Prevent stale or failed synthesis, cancellation, empty transcription, no speech, permission failure, page hiding, external playback preemption or ending the session from reopening the mic. The ten-second no-speech deadline ends the conversation; lack of a working analyser must not create an endless recording loop. Preserve sixty-second capture limit and silence stopping. Pressing End or Escape ends the session, cancels requests, releases tracks and timers. Ordinary push-to-talk remains available. Other automatic audio waits while capture/requests/playback own speech; the follow-up gap must not steal a newly claimed explicit player. Browser wake-word recognition must not run concurrently with the conversation loop.

Acceptance: (1) one dock persists across client navigation and is absent on login; browser checks on Bridge and another page confirm controls and fitting panels. (2) behavioral tests prove two user turns can chain after complete playback and prove all cancellation/error/quiet paths cannot reopen capture. (3) existing 43 voice/audio tests, new lifecycle tests, TypeScript and production build pass; independent spec and quality reviews precede scoped live rollout. No real microphone or external chat messages are used by automated verification.

Speech speed is a separate parent-owned change: 270 to 240 WPM in the local profile, with provider health accepting finite service-supported 100–350 WPM and briefing timing following observed speed. Voice reference and pitch remain unchanged. Groq input and existing wake-word technology stay in place. Local STT and streaming transport are outside this pass.
